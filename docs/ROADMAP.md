## 4. Roadmap rules

1. One stage at a time; each begins only with explicit owner authorization (D-002).
2. A stage's status changes only through a [DECISIONS.md](DECISIONS.md) entry — never by an AI's summary alone.
3. Historical reports keep their original internal numbering. This file maps them; it does not rewrite them.
4. Finishing a stage does not authorize the next one.
5. Never report a carried-forward test as passed. Report what ran, what did not, and why.
6. The ₹0 objective is a constraint with measured limits, not a promise that hosting stays free at every scale.

## 5. Stage 3 is pre-evidenced — do not repeat it

The free-hosting test was partly performed early, during Stage 1, because the architecture question could not wait:

- a live Cloudflare Pages site, verified byte-identical to its source ([Report 12 §2](stage-1/12_nation_supremacy_deployment_and_resource_separation.md));
- a live Supabase project built only from repository migrations, with RLS and grants tested ([Report 12 §3–§5](stage-1/12_nation_supremacy_deployment_and_resource_separation.md));
- exactly-once resolution, complete rollback on injected failure, and measured cost per nation-turn (35.5 ms per 1,000-nation slot, ≈264 bytes per nation-turn) ([Report 11 §15](stage-1/11_free_tier_feasibility_results.md)).

When official Stage 3 runs, it **builds on this evidence**. What it still owes is what elapsed time or an owner decision could not supply: CF-01 (capacity target), CF-02 (backup/restore drill), CF-03 (twelve consecutive boundaries), CF-07 (billing read and quota alarms). Re-running the completed experiments is out of scope unless a Stage 2 design decision invalidates them — and if it does, say which decision and why.
