**Status vocabulary (Prompt 11B-C2/C3).** **PASS** — the original requirement is satisfied and direct, identifiable evidence demonstrates it. **PARTIAL** — some element is incomplete or inadequately evidenced. **FAIL** — the evidence contradicts the requirement. **BLOCKED** — required source material or evidence is unavailable. The original brief's `NOT RUN` status is not used here because every gate below was assessed; a gate that could not be assessed would be `BLOCKED`.

**Evidence rules.** A `PASS` row cites at least one existing file and at least one identifiable section or identifier in that file. The validator resolves every cited path, section heading and identifier (`WEP-`, `F-WEP-`, `WPC-`, `WPF-`, `WPA-`, `REQ-`, `D-`, `DD-`, `UD-`, `B11-`). A citation that does not resolve is an invalid evidence reference, not a pass.

## Independent audit record

1. **Criterion.** Each row was read against the preserved source criterion, not against an earlier summary of it.
2. **Primary and supporting evidence.** Every cited path was opened, every cited section heading and identifier was resolved, and the cited `WEP-` rule was checked to belong to the cited section of the main specification. A path or an identifier alone was not accepted as proof.
3. **Assessment.** A row is `PASS` only when the evidence demonstrates the criterion. A related document's existence, a validator check, or another gate's PASS is not evidence.
4. **Findings corrected in this audit.** Six primary citations named the wrong section (`P11B-08`, `P11B-13`, `P11B-23`, `P11B-28`, `P11B-40` and the `P11B-42` lettered-rule resolution). The audit also found that mandatory check #20 of the original brief — all 11A recommendations dispositioned — was unmet: eight `11A-DR` IDs were absent and no 34-row disposition existed. A disposition table in §23.1, immediately after `WEP-692`, now records all 34; `B11-20` and `NEG-44` enforce it.
5. **Limits.** This is a documentary audit. It does not prove authorship, semantic sufficiency, gameplay behaviour, runtime execution or balance. `B11-60`/`B11-61` prove source-block integrity and criterion equality only. The C3 authentication confirms the located record's content and hashes; it does not cryptographically prove who wrote the prompt.

## Reporting rules

1. The **52 acceptance gates** are the original Prompt 11B §23 gates. The **61 B-11 validator checks** (`B11-01`…`B11-61`) are documentation-quality checks. The two counts are never added, substituted or equated.
2. A gate is `PASS` only when its primary evidence exists, its cited section or identifier resolves and the evidence demonstrates the criterion. A related document's existence is not sufficient.
3. `PARTIAL`, `FAIL` and `BLOCKED` rows are excluded from the `PASS` total. The four status counts must equal the gates accounted for.
4. Missing gates, duplicate gate identifiers, unknown gate identifiers, missing evidence and broken evidence references are validator failures.
5. Documentation link validation is a separate command (`python docs/qa_backups/validate_links.py`) and is not counted as acceptance-gate coverage.
