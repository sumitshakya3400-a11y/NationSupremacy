## 1. How to read this register

### 1.1 What this file is and is not

This file records **evidence**, not rules. Nothing here approves a Nation Supremacy fair-play rule, penalty, permission, data class, retention period or implementation. Approved positions live only in [DECISIONS.md](../../DECISIONS.md), the [04 design register](../04_approved_and_provisional_decisions.md) and the canonical subsystem rulebooks. Where a row describes what another game or organisation does, that is a report about **that** system, not a proposal that Nation Supremacy copies it. Design consequences are drawn out separately as numbered recommendations (`12A-DR-###`) in the companion report.

### 1.2 Identifier convention

| Namespace | Meaning | Range |
|---|---|---|
| `12A-RS-###` | One external research source row | `12A-RS-001` … `12A-RS-152` in §2–§6, contiguous with no gaps |
| `12A-BM-###` | One benchmark **mechanism** entry — a comparison of an underlying design, not a feature list | `12A-BM-001` … `12A-BM-040` |
| `12A-CMP-##` | One comparator-platform profile | `12A-CMP-01` … `12A-CMP-18` |

This file creates **no** global `REQ-`, `D-`, `DD-`, `UD-`, `SEC-`, `TH-`, `ST-` or `OSQ-` identifier. Stage-1 Report 08's namespaces are reused **by reference only** and never renumbered. Every `12A-` identifier carries a letter segment between the two hyphens, so it cannot be confused with Stage-1 Report 5's internal section labels of the form `§12A-9`.

### 1.3 Source-type vocabulary (mandatory on every row)

| Type | Meaning | Weight |
|---|---|---|
| `LEGISLATION` | Treaty, regulation, directive, statutory code | Highest for obligations; jurisdiction-conditional |
| `REGULATOR` | Supervisory-authority guidance, enforcement decisions, codes | High for interpretation; binding only where it quotes an obligation |
| `STANDARDS` | IETF, OWASP, NIST, ISO/IEC and similar catalogues | High for method; voluntary unless contractually invoked |
| `OFFICIAL-OPERATOR` | The operator of the system described, about its own product | High for **what that product does**; zero for how well it works |
| `OFFICIAL-VENDOR` | Platform or infrastructure documentation | High for platform mechanics and limits |
| `PEER-REVIEWED` | Reviewed paper, journal or proceedings | High for measured findings; check the setting |
| `PREPRINT` | Not independently reviewed | Indicative; never load-bearing alone |
| `INDUSTRY` | Conference session or named-practitioner engineering write-up | Medium; self-reported |
| `TERTIARY` | Encyclopaedic or aggregator content | Context only |
| `COMMUNITY` | Player or third-party reporting | Reported experience, not verified fact |
| `RETRIEVAL-FAILED` | Could not be read in this environment | **Metadata only — never load-bearing** |

### 1.4 Confidence vocabulary

`High` — read directly from a primary source, or measured in reviewed work whose setting matches the claim. `Medium` — read directly but self-reported, indirect, or a different setting. `Low` — snippet, secondary, archived, or disputed. `Unverified` — could not be read; recorded so a later pass does not re-derive it from a guess.

### 1.5 Access date and retrieval honesty

All rows were accessed **2026-11-06**. Machine retrieval was refused by several primary authorities; the refusals are recorded in §9 and the affected rows are downgraded rather than quietly dropped. In particular, **GDPR article numbering was read from a non-commercial mirror of the Official Journal text and independently corroborated inside regulator PDFs** (EDPB Guidelines 01/2025 and 9/2022) and a vendor DPA; it was **not** read from EUR-Lex, which returned an empty HTTP 202 body. Any claim resting on a blocked primary source is marked `Low` or `Unverified`.

**Reference capture is not uniform, and this register does not pretend it is.** Nineteen of the 152 rows carry a title-and-publisher reference with no URL: two are cross-references to another row that holds the link (`12A-RS-122`, `12A-RS-123`), fifteen state `URL not captured in this pass` because they were read as search-index excerpts or through a text-extraction proxy, one (`12A-RS-037`) is an index record only, and one (`12A-RS-152`) is this pass's own search log. Every such row says so in its own reference cell rather than presenting an unverified link; four further rows are cited by arXiv identifier and carry the resolver link for it. The `12A-03` validator check enforces that each row is either a live URL or one of these explicit disclosures.

### 6.2 What Register E changed in the design

Six findings materially altered the direction and are carried into §13–§19 and §27 of the report:

1. **GDPR Art. 22 makes human-in-the-loop a compliance obligation, not only a value** — for a server-automated game the "solely automated processing… similarly significantly affects" test is closer, not further, than in a realtime title (`12A-RS-134`). `D-018` already forbade single-signal bans, so this confirms rather than changes the policy, and it now has an external citation.
2. **A statement of reasons is a projection, not new infrastructure.** DSA Art. 17 requires a "clear and specific statement of reasons… at the latest from the date that the restriction is imposed, **regardless of why or how it was imposed**" (`12A-RS-133`). Because the spine already records rule, evidence class, tier and actor, the notice can be generated from the audit record — which is why `12A-CR-058` is stated as a record property rather than a communication task.
3. **Appeal budgets are finite and published.** Jagex allows two appeals (`12A-RS-129`); Epic allows one per sanction (`12A-RS-132`). That gives `UD-059` a defensible shape — a small integer plus published non-appealable categories — without 12A choosing the number.
4. **A reversal duty can exist without a user appeal.** Valve removes an incorrectly issued ban automatically (`12A-RS-121`). Adopting the duty while rejecting the no-appeal design is the useful half of that precedent, and it complements `NET-046`.
5. **Tiers expressed in turns, not days.** A two-hour cadence makes "N boundaries", "feature frozen until" and "excluded from this season's eligibility" more honest than day counts a single adjudicator cannot calibrate (`12A-RS-126`, `12A-RS-124`, `12A-RS-125`).
6. **Integrity claims must be exercised and, ideally, observable.** CloudTrail verification is opt-in and manual (`12A-RS-142`); Certificate Transparency works because the log is publicly auditable (`12A-RS-143`); RFC 3161 supplies external proof-of-existence (`12A-RS-144`). Together they justify a periodic published signed root — a control *stronger* than an internal check precisely because the operator is one unaudited person, and the best available answer to `RK-023` and `RK-026` at this staffing level.

### 6.3 Premise corrections this register makes

Three claims carried into the research brief turned out to be wrong or unsupported, and correcting them changes the compliance framing:

| Claim as given to this pass | What was actually found |
|---|---|
| "Italian AGCM fines on Blizzard (Diablo Immortal)" | AGCM **opened investigations** in January 2026 (`12A-RS-135`); no concluded fine was found in any source retrieved |
| "Italian AGCM fine on EA (Ultimate Team)" | AGCM **accepted EA's commitments and closed the case without ascertaining any infringement** (`12A-RS-136`); the €10 m action was **Dutch** (`12A-RS-137`) and was **overturned on appeal** by the Council of State in 2022 (`12A-RS-138`) |

The consequence is a clean separation: **conduct moderation** and **item-economy or monetisation exposure** are different risk surfaces before different regulators, and a document that blurs them will mis-scope both. `12A-CR-048` therefore names undeclared real-value exchange as a conduct category while the compliance statement keeps consumer and gambling regulation as a separate owner-and-counsel dependency under `UD-017`.
