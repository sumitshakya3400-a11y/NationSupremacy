# Prompt 11A integration, risk and candidate-requirement registers

**Companion to:** [`11A_world_events_objectives_rankings_progression_research.md`](11A_world_events_objectives_rankings_progression_research.md)
**Version:** 1.0 · **Created:** 2026-11-05 · **Stage 2, Prompt 11A** · **Research and documentation only**
**Purpose:** Record every cross-system integration for world events, objectives, rankings and long-term progression with the required fields; record every abuse and manipulation pattern Prompt 11 must design against; and state the candidate requirements that **Prompt 11B** must convert into formal rules.
**Status:** Research record. **No integration, risk control or candidate requirement is approved by being listed here.** Nothing is implemented. No existing owning rule is modified by any row.

## 1. How to read these registers

### 1.1 Identifier conventions

| Prefix | Meaning | Nature |
|---|---|---|
| `11A-INT-###` | A cross-system integration finding | Research identifier |
| `11A-RK-###` | An abuse, manipulation or integrity risk | Research identifier |
| `11A-CR-###` | A **candidate requirement** for Prompt 11B | Research identifier — **not** a `REQ-` row |
| `11A-OPEN-###` | An unresolved research question | Research identifier |
| `11A-DR-###` | A design recommendation | Carried in the main report |
| `11A-RS-###`, `11A-BM-###` | Source evidence and benchmark mechanics | Carried in [`11A_comparator_sources_and_benchmarks.md`](11A_comparator_sources_and_benchmarks.md) |

**Deliberate non-adoption of `11A-DEC-###`.** The Prompt 11A brief lists `11A-DEC-###` as a possible identifier space. It is **not** used here, because the project already provides the appropriate convention: a Category B design decision is recorded as a **`D-###`** entry in [`../../DECISIONS.md`](../../DECISIONS.md) with a mirrored **`DD-###`** position in [`../04_approved_and_provisional_decisions.md`](../04_approved_and_provisional_decisions.md), and a Category C provisional matter is recorded as **Provisional** with its missing evidence named. Creating a second register for decisions that already have an ID is expressly forbidden by [`../../AUTONOMOUS_DECISION_POLICY.md`](../../AUTONOMOUS_DECISION_POLICY.md) §5 ("Creating a second register for a decision that already has an ID"). The mapping from each recommendation to its `D-`/`DD-` row is in the main report §22 and §23.

**Deliberate non-allocation of global `REQ-` and `UD-` IDs.** This is a **research** prompt. The established convention in this project is that research sub-prompts register **candidate** requirements and leave global allocation to the specification sub-prompt: Prompt 08A produced `DPR-###` and twelve candidate recommendations and added **no** `REQ-` row; Prompt 09A produced 84 candidate requirements and added none; Prompt 10A produced `WCR-01`…`WCR-44` and added none — the global `REQ-654`…`REQ-703` rows were allocated later by Prompt 10B. `11A-CR-###` follows that precedent exactly. The register maximum at the time of writing is therefore unchanged: **`REQ-703`, `D-143`, `DD-191`, `UD-049`**, and the next free IDs (`REQ-704`, `D-144`, `DD-192`, `UD-050`) remain for **Prompt 11B**.

### 1.2 Integration field split

Each `11A-INT` row must carry the fifteen fields required by Prompt 11A §16. As in [`09A_alliance_integration_matrix.md`](09A_alliance_integration_matrix.md), rendering fifteen columns as one table is unreadable, so the fields are split:

- **§2 — fields 1–7** (ID, source subsystem, proposed relationship, trigger or data dependency, processing phase, owning subsystem, event/objective impact).
- **§3 — fields 8–15** (ranking impact, progression impact, accounting impact, privacy implications, exploit risks, existing governing rule, recommendation, outstanding dependency).
- **§4** states which owning rules a row would **violate** if ignored — the failure mode that matters most.

Every row names the owning rule by ID. Where no existing rule governs an aspect, the row says **NO EXISTING RULE** and names the prompt that must supply it; that is the absence of a rule, not a claim that Prompt 11 owns the behaviour.

### 1.3 Phase vocabulary

The phase names below are **B-02's**, not invented here: `TR-040` fixes P0 Prepare → P1 Freeze → P2 Re-validate → P3 Recurring → P4 Orders → P5 Conflict → **P6 World** → P7 Settle. `TR-040` assigns **P6 to Prompt 11** with the purpose "Evaluate objectives, rankings, systemic events", assigns P3's recurring political/event ticks partly to Prompt 11, and shares P7's record-writing and publication with Prompt 11. `TR-044` band **B4** is "world evaluation (events, objectives, rankings) — **Fixed evaluation order declared by Prompt 11**".
